# Package decisions

One line per package or component: version, where the practice came from, what we adopted. Checked with Context7 on 2026-09-24 unless noted.

| Package | Version | Source | Practice adopted |
| --- | --- | --- | --- |
| next | 16.3.6 | /vercel/next.js | App Router, Turbopack default, `reactCompiler: true`, `import { ViewTransition } from "react"` needs no config, route navigations are transitions. Async Server Components are not unit-testable in Vitest, so pages get Playwright coverage. |
| react | 19.3.0 | /reactjs/react.dev | `Activity`, `useEffectEvent`, `useOptimistic` are stable. `ViewTransition` ships through Next.js. |
| shadcn | 4.21.0 | /shadcn-ui/ui | `init -d` gives Base UI primitives and the nova preset. Add components with `pnpm dlx shadcn@latest add <name>`. |
| tailwindcss | 4.3.3 | shadcn init | CSS-first config in `src/app/globals.css`, `@custom-variant dark`. |
| drizzle-orm | 0.45.3 | /drizzle-team/drizzle-orm-docs | `drizzle-orm/node-sqlite` over Node's `node:sqlite` `DatabaseSync`; `db.transaction` with `behavior: "immediate"` for writes. |
| drizzle-kit | 0.31.11 | /drizzle-team/drizzle-orm-docs | `dialect: "sqlite"`, `dbCredentials.url` file path, `drizzle-kit push` for local. |
| @modelcontextprotocol/server | 2.1.0 | /modelcontextprotocol/typescript-sdk | `createMcpHandler(factory)` returns a web-standard fetch handler (fresh `McpServer` per request, stateless). `registerTool(name, { description, inputSchema: z.object }, handler)` returns `{ content, isError? }`. |
| @modelcontextprotocol/client | 2.1.0 | /modelcontextprotocol/typescript-sdk | Tests use `InMemoryTransport.createLinkedPair()` with `Client.callTool`. |
| zod | 4.6.5 | /colinhacks/zod | Import `* as z from "zod"`. `z.toJSONSchema` for exporting schemas, `.optional()`, `z.enum`. |
| usewebmcp | 5.1.0 | npm README | `useWebMCP({ name, description, inputSchema, execute, annotations, enabled }, deps)`; JSON Schema literals `as const` for input typing; `enabled: false` unregisters; aborts on unmount; needs `document.modelContext` to exist. |
| WebMCP (Chrome) | Chrome 149+ flag, 153 for unregister | developer.chrome.com/docs/ai/webmcp | `document.modelContext.registerTool(tool, { signal })`, `execute` returns a string, annotations `readOnlyHint` / `consequentialHint` / `untrustedContentHint`, name 30 chars, description 500, param description 150, output 1.5K. |
| motion | 13.4.2 | /websites/motion_dev | Import from `motion/react`. `useReducedMotion` gates animation. `AnimatePresence` + `layout` for list reflow, variants with `when` for stagger. |
| next-themes | 0.4.6 | /pacocoursey/next-themes | `<ThemeProvider attribute="class">` in the root layout, `suppressHydrationWarning` on `<html>`. |
| vitest | 5.0.1 | /vitest-dev/vitest | `resolve.tsconfigPaths: true` (Vite native, plugin not needed). `projects` split: node unit tests and a chromium browser project through `@vitest/browser-playwright`; projects inherit root plugins by default. |
| vitest-browser-react | 2.3.0 | /vitest-community/vitest-browser-react | `await render(<C/>)`, locators, `expect.element(...)` retries. |
| @playwright/test | 1.63.0 | /microsoft/playwright | `webServer` with `reuseExistingServer`, `env` for the test database, one worker because tests share one SQLite file. |
| drizzle-orm (revised) | 1.0.0-rc.4 | /drizzle-team/drizzle-orm-docs | 0.45 has no `node:sqlite` driver; the 1.0 release candidate does and matches the Context7 docs (migration folders per change, `migrate()` sync for node-sqlite). Writes use explicit `BEGIN IMMEDIATE` through `db.$client`. |
| @base-ui/react (via shadcn) | 1.x | /mui/base-ui | Event handlers are `(value, eventDetails)`. `Select` takes `items` for label lookup, `ToggleGroup` value is an array, `Dialog`/`AlertDialog` `onOpenChange(open)`. Links styled as buttons use `buttonVariants` on `<Link>` rather than `Button render` (which forces `role="button"`). |
| sonner | 2.0.8 | /emilkowalski/sonner | `<Toaster position richColors closeButton>` once in the layout, `toast(label, { description, id })` from the live provider. |
| mcp-remote | 0.14.3 | npm | stdio to Streamable HTTP bridge for Claude Desktop config. |
| Playwright ordering | 1.63 | /microsoft/playwright | `webServer` starts before global setup, so seeding is a `setup` project that resets rows in place. Each spec reseeds in `beforeAll`. Next 16 refuses two dev servers in one dir, so the e2e server uses `NEXT_DIST_DIR=.next/e2e`. |
| Vitest browser mode | 5.0.1 | /vitest-dev/vitest | Tests import `src/app/globals.css` in the setup file, otherwise unstyled Base UI controls have zero size and clicks time out. `next/link` renders outside Next once a minimal `process.env` exists. |
| React 19.3 lint rules | eslint-config-next 16 | react-hooks | No `setState` in effects (derive from props during render, or remount with `key`); `useEffectEvent` results stay inside the component. |
| shadcn combobox (Base UI) | 4.21.0 | /shadcn-ui/ui, /mui/base-ui | Grouped tree picker uses `items` as `{ value, items }` groups with `ComboboxGroup items` and `ComboboxCollection`. Object items need `itemToStringLabel` for the input text and `isItemEqualToValue` for controlled values; `itemToStringValue` is only the form value. |
| Migration for brands and models | drizzle-kit 1.0.0-rc.4 | /drizzle-team/drizzle-orm-docs | `generate --hints` resolves the new column, then the SQL was hand-edited to copy brands and models out of the old car rows and rebuild `cars` (SQLite cannot add a NOT NULL foreign key column to a populated table). Migrations run with foreign keys off, then `PRAGMA foreign_keys = ON`. |
| Filter layout | shadcn 4 (Sheet, ToggleGroup, Combobox, Select, Switch) | /shadcn-ui/ui | Faceted sidebar built directly in code rather than through a design tool: sticky panel with uppercase section labels, pill toggles for short enum lists, color swatches, selects for numeric ranges, a results toolbar with removable chips, and the same panel in a left Sheet under `lg`. |
| Intercepting routes | Next.js 16.3 | /vercel/next.js | `app/@modal/(.)book/[carId]` renders the car in a centered Dialog on soft navigation from the list; `app/book/[carId]/page.tsx` is the full page for direct loads. `@modal/default.tsx`, `@modal/page.tsx`, and `@modal/[...catchAll]` return null so the slot closes on other routes. Closing calls `router.back()`; day links use `replace` so back lands on the list, not on a previous day. |
| node:sqlite foreign keys | Node 24 | nodejs.org/api/sqlite | `DatabaseSync` enables foreign keys by default; migrations run with `PRAGMA foreign_keys = OFF` so table rebuilds do not cascade into child rows, then turn them on. |
| Browse frame | Tailwind 4, shadcn ScrollArea | /mui/base-ui | On `lg` and up the browse page is a min-height frame below the header: a toolbar row (title, count, chips, view toggle), then the filter sidebar and the results. The sidebar never scrolls; the row is as tall as the window or the sidebar, whichever is taller, and the results column is an absolutely positioned box inside that row so it matches the height without adding to it. Base UI sets `position: relative` inline on the ScrollArea root, so the absolute box is a wrapper around it. Content inside the viewport is wrapped in a `relative` div so sr-only labels cannot escape the clip. Below `lg` the page scrolls normally and filters open in a sheet. |
| react-day-picker (shadcn calendar) | 10.0.1 | /gpbl/react-day-picker | `mode="single" required` with controlled `selected`/`onSelect`, `disabled` as a matcher function (days without free slots), a custom `full` modifier with `modifiersClassNames`, controlled `month`, `startMonth`/`endMonth` from the schedule, `weekStartsOn={1}`. Day buttons are labelled like "Thursday, October 1st, 2026, selected", which the tests match on. Picking a day sets `?date=` with `router.replace`. |
| Live indicator | app | user request | Hidden while the stream is healthy (screen-reader-only status), visible only as Connecting or Reconnecting. |
| Car photos | next/image, shadcn Carousel (embla-carousel-react 8.6) | /vercel/next.js, /shadcn-ui/ui | Photos live in a `car_images` table (url, credit, source url, order). `images.remotePatterns` allows `upload.wikimedia.org` and `thumb.wikimedia.org`. Cards and the detail view both use the carousel (`variant="card"` is compact: small dots, hover arrows, no caption). A card is a container, not a link: the carousel controls sit on top, the body is the accessible link, and each photo carries an `aria-hidden` link so clicking the picture also opens the car. Hover scales the photo slightly, never the card. Cars without photos fall back to the silhouette. |
| Demo fleet data | Wikimedia Commons API | commons.wikimedia.org/w/api.php | Ten Volvo models with illustrative specs. Photos were selected by a script (landscape, at least 1400px wide, CC BY, CC BY-SA, or CC0) and saved to `src/db/volvo-images.json` with licence and author for attribution. The API rate-limits bursts, so the script pauses between requests. Tests keep the fictional fleet. |
| Local car photos | sharp 0.34 | npm | Hot-linking through the Next image optimizer hit Wikimedia's rate limit (429), so `scripts/fetch-car-images.ts` downloads each photo once with a User-Agent, resizes it to 1600px with sharp, saves it under `public/cars`, and records `localPath` in the JSON. Remote URLs from admins are shown `unoptimized` unless the host is allow-listed. |
| WebMCP in Chrome 153 (observed) | Chrome 153.0 | live check | `document.modelContext` exposes `getTools`, `registerTool`, `executeTool`, `ontoolchange`. `executeTool(tool, args)` takes the arguments as a JSON string (an object throws "Failed to parse input arguments") and returns the tool's result as a string. Tool objects carry `origin`, `title`, and `window`. |
| Generated placeholder | none (pure SVG) | user request | `placeholderPalette(id)` hashes the id (FNV-1a) into a muted HSL background, a lighter accent for the gradient, and white or ink text, darkening the background until the text meets WCAG AA 4.5:1 (tested for 200 ids). `CarPlaceholder` renders it as inline SVG with brand, model, body type, color, and a faint silhouette. The Commons photos, the download script, sharp, and the JSON were removed because the published demo cannot ship them; admins can still add photo URLs per car. |
| Code review pass | /code-review | review findings | Slot generation validates duration (5 to 240 minutes) and caps ranges at 366 days; lookups and bookings ignore inactive cars; slots that already started are marked `past` and cannot be booked; car enums are validated on write; `addModel` lives in the service; `findCar` resolves names in SQL instead of loading the fleet; facets query without images; event listeners are isolated; an impossible `?date=` falls back to the default day; the ISO day pattern and event type list are shared constants. |
| Vercel agent skills audit | vercel-react-best-practices, vercel-composition-patterns, vercel-react-view-transitions, vercel-optimize (installed under .agents/skills) | skills.sh | Applied: params and searchParams awaited in parallel; one cached car lookup per request (`React.cache`); Map lookups for colors, brand grouping, and facet order; single-pass slot grouping and admin summary; `cars` passed once to the slot generator; results view stored in a cookie and read on the server (no hydration flicker) with a `ViewTransition` cross-fade; WebMCP toggle is session-only by request; contexts expose `{ state, actions }` and are read with `use()`; filters live behind a `FilterProvider` instead of prop drilling; `CarBookingPage`/`CarBookingModal` and `CarPhotoCard`/`CarPhotoDetail` replace boolean and variant props; admin tabs and the header take children; `revalidatePath` is scoped per route; the live refresh skips routes the event cannot change; redundant `force-dynamic` removed; view transition CSS: no root cross-fade (live root), named isolation for header, toaster, modal, and sheet, `pointer-events: none` during transitions, timing variables, reduced motion by zero duration. Skipped on purpose: the card-to-detail shared morph (it can never pair, since the list stays mounted under the modal) so the names are gone; directional `transitionTypes` slides (optional polish); a booking-UI provider (the tools that drive it live outside the panel tree); server action auth (the demo has no accounts, noted in docs/deploy-vercel.md); localStorage inline scripts (replaced by the cookie). |
